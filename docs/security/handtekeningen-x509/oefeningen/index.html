Oefeningen: 2FA, Handtekeningen en X.509

Werk de oefeningen in volgorde. Elke oefening bouwt verder op de vorige. Kijk niet vooraf in de oplossingen.

Je werkt verder in de bestaande ShopWave-solution. Nieuwe klassen maak je aan in ShopWave/Security/. Nieuwe testklassen maak je aan in ShopWave.Tests/.

Oefening 1: TwoFactorService testen​

Leerdoel: je leert tests schrijven voor een klasse met tijdsafhankelijk gedrag en verifieert dat codes eenmalig bruikbaar zijn.

Moeilijkheidsgraad: basis

Situatie: TwoFactorService uit de demo genereert en verifieert 2FA-codes. Je schrijft de tests die bewijzen dat de beveiligingsregels correct geïmplementeerd zijn.

Wat je doet:

Maak ShopWave.Tests/TwoFactorServiceTests.cs aan en schrijf tests voor de volgende zes scenario's:

  1. Een gegenereerde code voor een e-mailadres is niet leeg
  2. De correcte code wordt geaccepteerd als geldig
  3. Een foute code wordt geweigerd
  4. Een code voor een onbekend e-mailadres wordt geweigerd
  5. Een code kan maar één keer gebruikt worden: de tweede verificatie met dezelfde code faalt
  6. Een verlopen code wordt geweigerd

Tip voor scenario 6: maak de TwoFactorService aan met validitySeconds: 0 zodat de code onmiddellijk verloopt. Voeg daarna System.Threading.Thread.Sleep(10) toe zodat de vervaltijd zeker bereikt is.

Startcode:

using FluentAssertions;
using ShopWave.Security;

namespace ShopWave.Tests
{
    public class TwoFactorServiceTests
    {
        [Fact]
        public void GenerateCode_ForValidEmail_ReturnsNonEmptyCode()
        {
            // Arrange
            TwoFactorService service = new TwoFactorService();

            // Act
            string code = service.GenerateCode("alice@shopwave.be");

            // Assert
            // jouw assertion hier
        }

        // Voeg de overige vijf tests zelf toe
    }
}

Verwacht resultaat:

✓ GenerateCode_ForValidEmail_ReturnsNonEmptyCode
✓ VerifyCode_WithCorrectCode_ReturnsTrue
✓ VerifyCode_WithWrongCode_ReturnsFalse
✓ VerifyCode_ForUnknownEmail_ReturnsFalse
✓ VerifyCode_UsedCodeVerifiedAgain_ReturnsFalse
✓ VerifyCode_ExpiredCode_ReturnsFalse

Oefening 2: AccountRepository testen met de callback-techniek​

Leerdoel: je leert de callback-techniek gebruiken om een gegenereerde 2FA-code op te vangen in een test, zonder mocks en zonder console-output.

Moeilijkheidsgraad: gemiddeld

Situatie: de AccountRepository uit de demo gebruikt een Action<string, string>-callback om de 2FA-code door te geven. In tests gebruik je die callback om de code op te vangen en daarna in VerifyTwoFactor te gebruiken.

Wat je doet:

Maak ShopWave.Tests/AccountRepositoryTwoFactorTests.cs aan en schrijf tests voor de volgende vijf scenario's:

  1. Na een correcte loginpoging retourneert Login de string "2FA vereist."
  2. Na een correcte loginpoging wordt de callback precies eenmaal aangeroepen met het juiste e-mailadres
  3. VerifyTwoFactor met de code die de callback doorgaf, retourneert "Inloggen geslaagd."
  4. VerifyTwoFactor met een foute code retourneert "Ongeldige of verlopen 2FA-code."
  5. Na een mislukte loginpoging (fout wachtwoord) wordt de callback niet aangeroepen

Startcode:

using FluentAssertions;
using ShopWave.Security;

namespace ShopWave.Tests
{
    public class AccountRepositoryTwoFactorTests
    {
        [Fact]
        public void Login_WithCorrectPassword_Returns2FaVereist()
        {
            // Arrange
            string capturedCode  = string.Empty;
            string capturedEmail = string.Empty;

            TwoFactorService  twoFactor  = new TwoFactorService();
            AccountRepository repository = new AccountRepository(
                twoFactor,
                onCodeGenerated: (email, code) =>
                {
                    capturedEmail = email;
                    capturedCode  = code;
                });

            repository.Register("alice@shopwave.be", "wachtwoord123");

            // Act
            string result = repository.Login("alice@shopwave.be", "wachtwoord123");

            // Assert
            result.Should().Be("2FA vereist.");
        }

        // Voeg de overige vier tests zelf toe
    }
}

Tip voor scenario 3: gebruik capturedCode uit de callback als invoer voor VerifyTwoFactor. Zo ben je niet afhankelijk van een hardcoded code.

Verwacht resultaat:

✓ Login_WithCorrectPassword_Returns2FaVereist
✓ Login_WithCorrectPassword_InvokesCallbackWithEmail
✓ VerifyTwoFactor_WithCapturedCode_ReturnsGeslaagd
✓ VerifyTwoFactor_WithWrongCode_ReturnsOngeldig
✓ Login_WithWrongPassword_DoesNotInvokeCallback

Oefening 3: OrderSigner testen​

Leerdoel: je leert tests schrijven voor een klasse die asymmetrische cryptografie gebruikt en begrijpt wat elke test bewijst.

Moeilijkheidsgraad: gemiddeld

Situatie: OrderSigner ondertekent en verifieert orderdata. Je schrijft tests die bewijzen dat integriteitscontrole correct werkt.

Wat je doet:

Maak ShopWave.Tests/OrderSignerTests.cs aan. Maak het certificaat en de OrderSigner aan in de constructor van de testklasse, zodat je ze niet in elke test opnieuw hoeft aan te maken.

Schrijf tests voor minstens vier scenario's:

  1. Een handtekening van originele orderdata is geldig
  2. Een handtekening van gemanipuleerde orderdata is ongeldig
  3. Een lege string als orderdata levert een handtekening op die ook voor een lege string geldig verifieert
  4. Een handtekening gemaakt met certificaat A is niet geldig als je hem verifieert met certificaat B

Startcode:

using FluentAssertions;
using ShopWave.Security;
using System.Security.Cryptography.X509Certificates;

namespace ShopWave.Tests
{
    public class OrderSignerTests
    {
        private readonly X509Certificate2 _certificate;
        private readonly OrderSigner      _signer;

        public OrderSignerTests()
        {
            _certificate = CertificateHelper.CreateSelfSignedCertificate("ShopWave");
            _signer      = new OrderSigner(_certificate);
        }

        [Fact]
        public void Verify_OriginalOrderData_ReturnsTrue()
        {
            // Arrange
            string orderData = "ORD-001 | alice@shopwave.be | Laptop | 999.99 EUR";
            string signature = _signer.Sign(orderData);

            // Act
            bool result = _signer.Verify(orderData, signature);

            // Assert
            result.Should().BeTrue();
        }

        // Voeg de overige drie tests zelf toe
    }
}

Tip voor scenario 4: maak een tweede OrderSigner aan met een nieuw certificaat. Onderteken met de ene, verifieer met de andere.

Verwacht resultaat:

✓ Verify_OriginalOrderData_ReturnsTrue
✓ Verify_ManipulatedOrderData_ReturnsFalse
✓ Verify_EmptyString_ReturnsTrue
✓ Verify_SignatureFromDifferentCertificate_ReturnsFalse

Oefening 4: SecureOrderService implementeren en testen​

Leerdoel: je implementeert een klasse die OrderSigner intern gebruikt en schrijft de bijbehorende tests.

Moeilijkheidsgraad: uitdaging

Situatie: ShopWave wil een hoog-niveau service die orders aanmaakt en ondertekent in één stap. De rest van de applicatie hoeft niet te weten hoe certificaten werken.

Wat je doet:

Maak eerst ShopWave/Security/OrderResult.cs aan:

namespace ShopWave.Security
{
    public class OrderResult
    {
        public string OrderData { get; }
        public string Signature { get; }

        public OrderResult(string orderData, string signature)
        {
            OrderData = orderData;
            Signature = signature;
        }
    }
}

Maak daarna ShopWave/Security/SecureOrderService.cs aan met de volgende signatuur:

namespace ShopWave.Security
{
    public class SecureOrderService
    {
        public OrderResult CreateSignedOrder(
            string customerEmail,
            string productName,
            double price) { ... }

        public bool ValidateOrder(string orderData, string signature) { ... }
    }
}

Vereisten:

  • CreateSignedOrder bouwt een orderstring op in het formaat: "{customerEmail} | {productName} | {price:0.00} EUR" (gebruik CultureInfo.InvariantCulture zodat het decimaalscheidingsteken altijd een punt is, ook op Belgische systemen)
  • CreateSignedOrder ondertekent die string en retourneert een OrderResult
  • ValidateOrder verifieert of de handtekening overeenkomt met de orderdata
  • Het certificaat wordt intern aangemaakt via CertificateHelper

Maak daarna ShopWave.Tests/SecureOrderServiceTests.cs aan met minstens vier tests:

  1. CreateSignedOrder retourneert een OrderResult waarvan OrderData niet leeg is
  2. ValidateOrder met de originele orderdata en de bijhorende handtekening retourneert true
  3. ValidateOrder met gemanipuleerde orderdata retourneert false
  4. De prijs in OrderData gebruikt een punt als decimaalscheidingsteken, ongeacht de systeemtaal

Verwacht resultaat:

✓ CreateSignedOrder_ReturnsOrderResultWithNonEmptyData
✓ ValidateOrder_WithOriginalData_ReturnsTrue
✓ ValidateOrder_WithManipulatedData_ReturnsFalse
✓ CreateSignedOrder_Price_UsesDotAsDecimalSeparator
