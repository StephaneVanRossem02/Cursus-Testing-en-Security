Oplossingen: 2FA, Handtekeningen en X.509

Bekijk dit pas nadat je de oefeningen zelf geprobeerd hebt. Lees de toelichting ook als je het juist had.

Oplossing 1: TwoFactorService testen​

using FluentAssertions;
using ShopWave.Security;

namespace ShopWave.Tests
{
    public class TwoFactorServiceTests
    {
        [Fact]
        public void GenerateCode_ForValidEmail_ReturnsNonEmptyCode()
        {
            // Arrange
            TwoFactorService service = new TwoFactorService();

            // Act
            string code = service.GenerateCode("alice@shopwave.be");

            // Assert
            code.Should().NotBeNullOrEmpty();
        }

        [Fact]
        public void VerifyCode_WithCorrectCode_ReturnsTrue()
        {
            // Arrange
            TwoFactorService service = new TwoFactorService();
            string code              = service.GenerateCode("alice@shopwave.be");

            // Act
            bool result = service.VerifyCode("alice@shopwave.be", code);

            // Assert
            result.Should().BeTrue();
        }

        [Fact]
        public void VerifyCode_WithWrongCode_ReturnsFalse()
        {
            // Arrange
            TwoFactorService service = new TwoFactorService();
            service.GenerateCode("alice@shopwave.be");

            // Act
            bool result = service.VerifyCode("alice@shopwave.be", "000000");

            // Assert
            result.Should().BeFalse();
        }

        [Fact]
        public void VerifyCode_ForUnknownEmail_ReturnsFalse()
        {
            // Arrange
            TwoFactorService service = new TwoFactorService();

            // Act
            bool result = service.VerifyCode("onbekend@shopwave.be", "123456");

            // Assert
            result.Should().BeFalse();
        }

        [Fact]
        public void VerifyCode_UsedCodeVerifiedAgain_ReturnsFalse()
        {
            // Arrange
            TwoFactorService service = new TwoFactorService();
            string code              = service.GenerateCode("alice@shopwave.be");
            service.VerifyCode("alice@shopwave.be", code);

            // Act
            bool result = service.VerifyCode("alice@shopwave.be", code);

            // Assert
            result.Should().BeFalse();
        }

        [Fact]
        public void VerifyCode_ExpiredCode_ReturnsFalse()
        {
            // Arrange
            TwoFactorService service = new TwoFactorService(validitySeconds: 0);
            string code              = service.GenerateCode("alice@shopwave.be");
            System.Threading.Thread.Sleep(10);

            // Act
            bool result = service.VerifyCode("alice@shopwave.be", code);

            // Assert
            result.Should().BeFalse();
        }
    }
}

Toelichting​

Test 5 verifieert dat codes eenmalig zijn. In TwoFactorService staat _pendingCodes.Remove(email) buiten de if-controle. Dat betekent: of de code nu geldig is of niet, hij wordt altijd verwijderd na de eerste verificatiepoging. Test 5 bewijst dat dit correct werkt.

Test 6 gebruikt validitySeconds: 0. Dat maakt de code vervallen zodra hij aangemaakt is. Thread.Sleep(10) geeft de tijd 10 milliseconden om vooruit te gaan, zodat DateTime.UtcNow zeker na ExpiresAt valt.

Veelgemaakte fout: studenten schrijven de code-waarde als hardcoded string in de test, bijvoorbeeld service.VerifyCode("alice@shopwave.be", "482917"). Dat faalt bijna altijd, want GenerateCode genereert een willekeurige code. Vang de code altijd op in een variabele: string code = service.GenerateCode(...).

Veelgemaakte fout: studenten vergeten in test 3 eerst GenerateCode aan te roepen. Als er geen code gegenereerd is, bestaat het e-mailadres niet in _pendingCodes en retourneert VerifyCode false. Test 3 slaagt dan ook als de foute code geweigerd wordt om de verkeerde reden.

Oplossing 2: AccountRepository testen met de callback-techniek​

using FluentAssertions;
using ShopWave.Security;

namespace ShopWave.Tests
{
    public class AccountRepositoryTwoFactorTests
    {
        [Fact]
        public void Login_WithCorrectPassword_Returns2FaVereist()
        {
            // Arrange
            TwoFactorService  twoFactor  = new TwoFactorService();
            AccountRepository repository = new AccountRepository(twoFactor);
            repository.Register("alice@shopwave.be", "wachtwoord123");

            // Act
            string result = repository.Login("alice@shopwave.be", "wachtwoord123");

            // Assert
            result.Should().Be("2FA vereist.");
        }

        [Fact]
        public void Login_WithCorrectPassword_InvokesCallbackWithEmail()
        {
            // Arrange
            string capturedEmail = string.Empty;

            TwoFactorService  twoFactor  = new TwoFactorService();
            AccountRepository repository = new AccountRepository(
                twoFactor,
                onCodeGenerated: (email, code) => { capturedEmail = email; });

            repository.Register("alice@shopwave.be", "wachtwoord123");

            // Act
            repository.Login("alice@shopwave.be", "wachtwoord123");

            // Assert
            capturedEmail.Should().Be("alice@shopwave.be");
        }

        [Fact]
        public void VerifyTwoFactor_WithCapturedCode_ReturnsGeslaagd()
        {
            // Arrange
            string capturedCode = string.Empty;

            TwoFactorService  twoFactor  = new TwoFactorService();
            AccountRepository repository = new AccountRepository(
                twoFactor,
                onCodeGenerated: (email, code) => { capturedCode = code; });

            repository.Register("alice@shopwave.be", "wachtwoord123");
            repository.Login("alice@shopwave.be", "wachtwoord123");

            // Act
            string result = repository.VerifyTwoFactor("alice@shopwave.be", capturedCode);

            // Assert
            result.Should().Be("Inloggen geslaagd.");
        }

        [Fact]
        public void VerifyTwoFactor_WithWrongCode_ReturnsOngeldig()
        {
            // Arrange
            TwoFactorService  twoFactor  = new TwoFactorService();
            AccountRepository repository = new AccountRepository(twoFactor);
            repository.Register("alice@shopwave.be", "wachtwoord123");
            repository.Login("alice@shopwave.be", "wachtwoord123");

            // Act
            string result = repository.VerifyTwoFactor("alice@shopwave.be", "000000");

            // Assert
            result.Should().Be("Ongeldige of verlopen 2FA-code.");
        }

        [Fact]
        public void Login_WithWrongPassword_DoesNotInvokeCallback()
        {
            // Arrange
            bool callbackInvoked = false;

            TwoFactorService  twoFactor  = new TwoFactorService();
            AccountRepository repository = new AccountRepository(
                twoFactor,
                onCodeGenerated: (email, code) => { callbackInvoked = true; });

            repository.Register("alice@shopwave.be", "wachtwoord123");

            // Act
            repository.Login("alice@shopwave.be", "foutWachtwoord");

            // Assert
            callbackInvoked.Should().BeFalse();
        }
    }
}

Toelichting​

De callback-techniek laat je de gegenereerde code opvangen zonder TwoFactorService te mocken. De lambda (email, code) => { capturedCode = code; } slaat de code op in een lokale variabele die de test daarna kan gebruiken.

Test 3 is de belangrijkste. De volledige flow wordt getest: registreren, inloggen, code opvangen via callback, en verifiëren. Als één stap in die keten fouten bevat, faalt deze test.

Test 5 verifieert dat de callback niet aangeroepen wordt bij een fout wachtwoord. Dit is een beveiligingseis: een 2FA-code mag alleen gegenereerd worden als het wachtwoord correct is.

Veelgemaakte fout: studenten geven geen callback mee aan AccountRepository in test 3 en proberen de code via TwoFactorService te achterhalen. Dat werkt niet: TwoFactorService geeft de code niet terug nadat hij aangemaakt is. De callback is de enige manier om de code op te vangen.

Veelgemaakte fout: studenten maken een nieuwe AccountRepository aan in VerifyTwoFactor in plaats van dezelfde instantie te gebruiken. De toestand (de gegenereerde code in TwoFactorService) zit in de bestaande instantie. Een nieuwe instantie heeft geen weet van de eerder gegenereerde code.

Oplossing 3: OrderSigner testen​

using FluentAssertions;
using ShopWave.Security;
using System.Security.Cryptography.X509Certificates;

namespace ShopWave.Tests
{
    public class OrderSignerTests
    {
        private readonly X509Certificate2 _certificate;
        private readonly OrderSigner      _signer;

        public OrderSignerTests()
        {
            _certificate = CertificateHelper.CreateSelfSignedCertificate("ShopWave");
            _signer      = new OrderSigner(_certificate);
        }

        [Fact]
        public void Verify_OriginalOrderData_ReturnsTrue()
        {
            // Arrange
            string orderData = "ORD-001 | alice@shopwave.be | Laptop | 999.99 EUR";
            string signature = _signer.Sign(orderData);

            // Act
            bool result = _signer.Verify(orderData, signature);

            // Assert
            result.Should().BeTrue();
        }

        [Fact]
        public void Verify_ManipulatedOrderData_ReturnsFalse()
        {
            // Arrange
            string originalData    = "ORD-001 | alice@shopwave.be | Laptop | 999.99 EUR";
            string manipulatedData = "ORD-001 | alice@shopwave.be | Laptop | 1.00 EUR";
            string signature       = _signer.Sign(originalData);

            // Act
            bool result = _signer.Verify(manipulatedData, signature);

            // Assert
            result.Should().BeFalse();
        }

        [Fact]
        public void Verify_EmptyString_ReturnsTrue()
        {
            // Arrange
            string orderData = string.Empty;
            string signature = _signer.Sign(orderData);

            // Act
            bool result = _signer.Verify(orderData, signature);

            // Assert
            result.Should().BeTrue();
        }

        [Fact]
        public void Verify_SignatureFromDifferentCertificate_ReturnsFalse()
        {
            // Arrange
            X509Certificate2 otherCertificate = CertificateHelper.CreateSelfSignedCertificate("AndereServer");
            OrderSigner      otherSigner      = new OrderSigner(otherCertificate);

            string orderData = "ORD-001 | alice@shopwave.be | Laptop | 999.99 EUR";
            string signature = otherSigner.Sign(orderData);

            // Act
            bool result = _signer.Verify(orderData, signature);

            // Assert
            result.Should().BeFalse();
        }
    }
}

Toelichting​

Het certificaat en de OrderSigner worden aangemaakt in de constructor van de testklasse. xUnit maakt voor elke testmethode een nieuwe instantie van de testklasse aan. Elke test werkt dus met een vers certificaat. Dat is correct: certificaten zijn stateless en bevatten geen toestand tussen tests.

Test 3 met een lege string bewijst dat Sign niet faalt bij randgevallen. Een lege string heeft een geldige SHA-256-hash: e3b0c44298fc1c149afb.... SignData ondertekent die hash en VerifyData verifieert hem correct.

Test 4 bewijst het principe van asymmetrische cryptografie: de publieke sleutel van certificaat A kan alleen handtekeningen verifiëren die gemaakt zijn met de private sleutel van certificaat A. Een handtekening van certificaat B faalt altijd bij verificatie met certificaat A.

Veelgemaakte fout: studenten maken in test 4 twee OrderSigner-instanties met hetzelfde certificaat in plaats van twee verschillende certificaten. De test slaagt dan niet, want beide signers gebruiken dezelfde sleutels.

Veelgemaakte fout: studenten vergeten dat CreateSelfSignedCertificate bij elke aanroep een nieuw willekeurig sleutelpaar genereert. Twee aanroepen met dezelfde naam "ShopWave" geven twee verschillende certificaten met verschillende sleutels.

Oplossing 4: SecureOrderService​

OrderResult.cs​

namespace ShopWave.Security
{
    public class OrderResult
    {
        public string OrderData { get; }
        public string Signature { get; }

        public OrderResult(string orderData, string signature)
        {
            OrderData = orderData;
            Signature = signature;
        }
    }
}

SecureOrderService.cs​

using System.Globalization;
using System.Security.Cryptography.X509Certificates;

namespace ShopWave.Security
{
    public class SecureOrderService
    {
        private readonly OrderSigner _signer;

        public SecureOrderService()
        {
            X509Certificate2 certificate = CertificateHelper.CreateSelfSignedCertificate("ShopWave");
            _signer = new OrderSigner(certificate);
        }

        public OrderResult CreateSignedOrder(
            string customerEmail,
            string productName,
            double price)
        {
            string orderData = string.Format(
                CultureInfo.InvariantCulture,
                "{0} | {1} | {2:0.00} EUR",
                customerEmail,
                productName,
                price);

            string signature = _signer.Sign(orderData);

            return new OrderResult(orderData, signature);
        }

        public bool ValidateOrder(string orderData, string signature)
        {
            return _signer.Verify(orderData, signature);
        }
    }
}

SecureOrderServiceTests.cs​

using FluentAssertions;
using ShopWave.Security;

namespace ShopWave.Tests
{
    public class SecureOrderServiceTests
    {
        [Fact]
        public void CreateSignedOrder_ReturnsOrderResultWithNonEmptyData()
        {
            // Arrange
            SecureOrderService service = new SecureOrderService();

            // Act
            OrderResult result = service.CreateSignedOrder(
                "alice@shopwave.be", "Laptop", 999.99);

            // Assert
            result.OrderData.Should().NotBeNullOrEmpty();
            result.Signature.Should().NotBeNullOrEmpty();
        }

        [Fact]
        public void ValidateOrder_WithOriginalData_ReturnsTrue()
        {
            // Arrange
            SecureOrderService service = new SecureOrderService();
            OrderResult        order   = service.CreateSignedOrder(
                "alice@shopwave.be", "Laptop", 999.99);

            // Act
            bool result = service.ValidateOrder(order.OrderData, order.Signature);

            // Assert
            result.Should().BeTrue();
        }

        [Fact]
        public void ValidateOrder_WithManipulatedData_ReturnsFalse()
        {
            // Arrange
            SecureOrderService service = new SecureOrderService();
            OrderResult        order   = service.CreateSignedOrder(
                "alice@shopwave.be", "Laptop", 999.99);

            string manipulated = order.OrderData.Replace("999.99", "1.00");

            // Act
            bool result = service.ValidateOrder(manipulated, order.Signature);

            // Assert
            result.Should().BeFalse();
        }

        [Fact]
        public void CreateSignedOrder_Price_UsesDotAsDecimalSeparator()
        {
            // Arrange
            SecureOrderService service = new SecureOrderService();

            // Act
            OrderResult result = service.CreateSignedOrder(
                "alice@shopwave.be", "Laptop", 999.99);

            // Assert
            result.OrderData.Should().Contain("999.99");
            result.OrderData.Should().NotContain("999,99");
        }
    }
}

Toelichting​

CultureInfo.InvariantCulture in string.Format zorgt dat de prijsformattering altijd een punt gebruikt als decimaalscheidingsteken. Op een Belgisch systeem gebruikt .NET standaard een komma. Als je InvariantCulture vergeet, bevat OrderData "999,99 EUR" op een Belgisch systeem en "999.99 EUR" op een Engels systeem. Test 4 vangt die fout op.

order.OrderData.Replace("999.99", "1.00") simuleert een aanval waarbij een aanvaller de prijs in de orderstring wijzigt. De handtekening klopt niet meer met de gewijzigde data, dus ValidateOrder retourneert false.

Veelgemaakte fout: studenten maken in ValidateOrder een nieuwe SecureOrderService aan. Die heeft een nieuw certificaat en nieuwe sleutels. De handtekening die gemaakt is met het certificaat van de eerste instantie, kan nooit geldig zijn met de sleutels van een tweede instantie. Gebruik altijd dezelfde instantie voor zowel CreateSignedOrder als ValidateOrder.

Oplossing 5: CIA-koppeling​

Vraag 1: welke CIA-pijler beschermt 2FA?

Confidentiality. 2FA beschermt de toegang tot het account van de klant. Als een aanvaller het wachtwoord van een ShopWave-klant steelt via phishing, kan hij zonder de tweede factor niet inloggen. De persoonsgegevens, bestelgeschiedenis en betalingsgegevens van de klant blijven vertrouwelijk.

Vraag 2: welke CIA-pijler beschermt een digitale handtekening?

Integrity. Een digitale handtekening detecteert elke wijziging in de orderdata. Als een aanvaller de prijs van 999 EUR naar 1 EUR wijzigt, klopt de SHA-256-hash van de gewijzigde data niet meer met de hash in de handtekening. ValidateOrder retourneert false. De integriteit van de order is geborgd.

Vraag 3: prijsmanipulatie gedetecteerd

Het systeem merkt dat ValidateOrder false retourneert. De SHA-256-hash van de gemanipuleerde orderdata verschilt van de hash die in de handtekening zit. De aanvaller kan de handtekening niet aanpassen zonder de private sleutel van ShopWave. De CIA-pijler is Integrity: de data is gewijzigd en dat is detecteerbaar.

Vraag 4: AesEncryptor versus OrderSigner

AesEncryptor beschermt Confidentiality: de orderdata wordt onleesbaar gemaakt voor iedereen zonder de sleutel. Een aanvaller die de versleutelde data onderschept, kan de inhoud niet lezen.

OrderSigner beschermt Integrity: de orderdata blijft leesbaar, maar elke wijziging is detecteerbaar. Een aanvaller kan de inhoud lezen maar niet ongemerkt wijzigen.

In een volledig beveiligd systeem gebruik je beide: je versleutelt de orderdata (confidentiality) én je ondertekent ze (integrity).
